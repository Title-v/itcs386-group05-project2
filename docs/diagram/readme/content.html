02

TEST DESIGN · INPUT SPACE PARTITIONING

แบ่ง “โลกของอินพุต” ก่อนเลือกตัวอย่าง

Input Space Partitioning (ISP) จัดอินพุตหรือเงื่อนไขตั้งต้นที่คล้ายกันให้อยู่ในกลุ่มเดียวกัน เรียกว่า block แล้วเลือกตัวแทนจากแต่ละกลุ่ม แทนการลองค่าจำนวนมากแบบไม่มีหลัก

Characteristic

คุณสมบัติที่แบ่งกลุ่ม

เช่น จำนวนสินค้าต่อหน้า หรือสถานะการเผยแพร่

Block

กลุ่มค่าที่มีความหมายร่วม

เช่น per_page ที่ถูกช่วง 1–100 หรือค่าต่ำกว่าขอบเขต

Base choice

ชุดปกติที่ใช้เทียบ

เลือกค่าปกติที่ทำงานร่วมกันได้ แล้วเปลี่ยนทีละ characteristic

Base Choice Coverage (BCC)
1 + Σ (จำนวน blocks ของแต่ละ characteristic − 1)

นับ base case หนึ่งครั้ง แล้วเพิ่มกรณีสำหรับ block ที่ไม่ใช่ base ของแต่ละคุณสมบัติ เมื่อชุดค่าทำงานร่วมกันได้

BCC cases สร้างจากการเปลี่ยน block ทีละ characteristic
Boundary probes ตรวจค่าขอบเขตเพิ่ม เช่น 1 และ 100; ไม่ได้แปลว่าเป็น block ใหม่

โมเดลนี้จำกัดเฉพาะส่วนที่ประกาศไว้ ไม่ได้อ้างว่าครอบคลุมทุก filter ทุกค่าผิดรูปแบบ หรือทุก combination และไม่ได้อ้าง Pair-Wise หรือ All Combinations Coverage

ก่อนรัน: ตรวจบัญชีและเชื่อมต่อให้พร้อม

runner เริ่มด้วยการสร้าง run ID และใช้ pytest เรียกทั้งสามไฟล์ตามลำดับปกติ จากนั้น shop_config ตรวจว่ามี SHOP_USER และ SHOP_API_PASSWORD, username เป็นบัญชีที่กำหนด และ run ID รูปแบบถูกต้อง ก่อนทำ Admin read preflight ถ้า preflight ไม่ผ่านจะ fail ก่อนสร้างสินค้า

เครื่องมือแต่ละตัวทำอะไร: Python คือภาษาเขียน test; pytest ใช้ค้นหาและรันกรณีทดสอบพร้อมตรวจ assertions; requests เป็นไลบรารีที่ส่ง HTTP requests ไปยัง Store/Admin API เวอร์ชันที่ pin สำหรับ dependencies คือ pytest 9.2.0 และ requests 2.34.2 ตาม requirements.txt
